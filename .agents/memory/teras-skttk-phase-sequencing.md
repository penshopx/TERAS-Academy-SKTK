---
name: TERAS SKTTK phase sequencing
description: The locked implementation order connecting the competency framework, personal diagnostic, LMS, and readiness rules.
---

Keep Path B closed: SKTTK data, schema, and knowledge work are not started, including hidden preparation or assumed integration. Path B begins only after the explicit declaration: “Path B — TERAS SKTTK resmi dimulai.”

After that declaration, keep the Phase 1 foundation locked. Complete the SKTTK Competency Framework first, then perform an Integration Review across the framework, Personal Diagnostic, and existing LMS. Build the Personal Diagnostic & Readiness Map only after that review, and build configurable readiness rules afterward.

**Why:** The explicit trigger prevents recovery, hardening, or unrelated assignments from being mistaken for the start of Path B. Once opened, the diagnostic must compare a learner's current state against concrete competency units, elements, KUK, and their knowledge, practice, safety, and evidence requirements. Building it first would create generic categories that later require rework.

**How to apply:** Before the trigger, do not modify or prepare SKTTK data, schema, or knowledge. Continue only within each assignment's own gate. After the trigger, do not duplicate active framework work; verify that framework entities can be referenced by diagnostic questions and existing LMS objects before diagnostic implementation. Preserve the existing readiness engine until the later readiness-rules phase.
