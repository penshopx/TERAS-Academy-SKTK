Keep Path B closed: SKTTK data, schema, and knowledge work are not started, including hidden preparation or assumed integration. Existing preview pages, “SKTTK Readiness” branding, and certification-preparation language are UI only; they are not evidence that Path B has opened or that any SKTTK domain integration exists. Path B begins only after the explicit declaration: “Path B — TERAS SKTTK resmi dimulai.”

After that declaration, keep the Phase 1 foundation locked. Complete the SKTTK Competency Framework first, then perform an Integration Review across the framework, Personal Diagnostic, and existing LMS. Build the Personal Diagnostic & Readiness Map only after that review, and build configurable readiness rules afterward.

**Why:** The explicit trigger prevents recovery, hardening, unrelated assignments, or visible UI branding from being mistaken for the start of Path B. Once opened, the diagnostic must compare a learner's current state against concrete competency units, elements, KUK, and their knowledge, practice, safety, and evidence requirements. Building it first would create generic categories that later require rework.

**How to apply:** Before the trigger, report Path B as CLOSED and SKTTK data, schema, and knowledge as NOT STARTED. Do not infer governance state from screenshots, routes, page copy, or branding, and do not modify or prepare those domain layers. Continue only within each assignment's own gate. After the trigger, do not duplicate active framework work; verify that framework entities can be referenced by diagnostic questions and existing LMS objects before diagnostic implementation. Preserve the existing readiness engine until the later readiness-rules phase.
