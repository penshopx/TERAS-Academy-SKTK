# TERAS SKTTK — Final Agentic Architecture

## 1. Posisi produk

TERAS SKTTK bukan AI yang memberikan keputusan sertifikasi.

Posisinya:

> **AI-powered competency readiness platform yang membantu tenaga teknik mempersiapkan diri, menemukan gap, menyusun remediation, mengelola evidence persiapan, dan mencapai readiness sebelum proses asesmen resmi.**

Batas otoritas tetap:

```text
TERAS
Persiapan
   ↓
AI Readiness Support
   ↓
Preparation Evidence
   ↓
Internal Simulation
   ↓
Readiness
   ↓
──────────────
Asesor / LSP
   ↓
Asesmen & keputusan resmi
```

AI **tidak** mengeluarkan keputusan kompetensi resmi.

# 3. Agent yang menjadi kanonik

Saya tidak akan membuat satu **“TERAS Super Agent”**.

Kita buat agent berdasarkan fungsi.

### 01 — TERAS Navigator Agent

Tugas:

* memahami posisi peserta;
* menjelaskan journey;
* menentukan next step;
* menemukan aktivitas yang belum selesai.

Contoh:

> “Saya sudah menyelesaikan diagnostic. Apa berikutnya?”

---

### 02 — TERAS Diagnostic Agent

Menganalisis hasil diagnostic.

Output:

```text
Current capability
Knowledge gaps
Practice gaps
Safety concerns
Evidence gaps
Recommended next action
```

Bukan keputusan sertifikasi.

---

### 03 — TERAS Learning Agent

Membantu personalisasi pembelajaran.

```text
Diagnostic
   ↓
Gap
   ↓
Learning content
   ↓
Practice
   ↓
Feedback
```

---

### 04 — TERAS Practice Agent

Menyediakan simulasi dan latihan.

Agent dapat:

* membuat scenario;
* memberikan pertanyaan;
* menilai jawaban terhadap rubric internal;
* memberikan feedback;
* menentukan remediation.

Tetapi hasilnya tetap:

> **internal learning/simulation result**

bukan hasil asesmen resmi.

---

### 05 — TERAS Evidence Agent

Ini salah satu agent paling penting.

Tugas:

```text
Requirement
   ↓
Expected preparation evidence
   ↓
Existing evidence
   ↓
Gap
   ↓
Evidence improvement
```

AI tidak boleh menyatakan:

> “Ini adalah bukti kompetensi resmi.”

Istilah kanonik:

> **Preparation Evidence**

---

### 06 — TERAS Remediation Agent

Jika peserta belum siap:

```text

 ↓
Root cause
 ↓
Remediation plan
 ↓
Practice
 ↓
Evidence
 ↓
Reassessment
```

Jadi remediation tidak lagi sekadar daftar materi.

Ia menjadi **closed-loop improvement system**.

---

### 07 — TERAS Readiness Agent

Menganalisis keseluruhan perjalanan.

Output hanya menggunakan status yang sudah kita tetapkan:

```text
NEEDS STRENGTHENING

NOT READY
```

Dan:

**Safety Gate tetap menjadi blocker.**

AI tidak boleh "menghaluskan" critical safety failure hanya karena skor lainnya tinggi.

# 8. Permission model

Saya akan menetapkan tiga level.

### READ

AI boleh membaca.

### PROPOSE

AI boleh membuat rekomendasi/draft.

### EXECUTE

AI boleh melakukan tindakan yang secara eksplisit diizinkan.

Contoh:

| Action                             | AI                    |
| ---------------------------------- | --------------------- |
| Membaca progress                   | READ                  |
| Menjelaskan gap                    | READ                  |
| Membuat learning recommendation    | PROPOSE               |
| Membuat draft remediation          | PROPOSE               |
| Mengirim review ke trainer         | EXECUTE dengan policy |
| Mengubah hasil trainer             | **DENY**              |
| Mengubah readiness resmi           | **DENY**              |
| Mengeluarkan keputusan sertifikasi | **DENY**              |

## Kesimpulan final

Saya akan menjadikan prinsip berikut sebagai **North Star TERAS Agentic**:

> **TERAS tidak menggunakan AI untuk menggantikan asesor, trainer, atau LSP. TERAS menggunakan AI untuk mempercepat pembelajaran, memperjelas gap, memperbaiki evidence persiapan, mengorkestrasi remediation, dan meningkatkan readiness secara dapat diaudit.**

Dan secara teknis:

> **TERAS Core = source of truth.**
> **Agentic Control Plane = intelligence & orchestration.**
> **Hermes = reasoning/memory runtime.**
> **MultiClaw = multi-agent orchestration.**
> **OpenClaw = execution/integration runtime.**
> **MCP = standardized tool boundary.**
> **Policy Engine = guardrail.**
> **Human = authority.**
> **Audit = accountability.**

**Untuk sekarang tidak ada perubahan pada Task #168 dan tidak ada implementasi Path B.** Blueprint ini menjadi rancangan target yang dapat kita gunakan setelah boundary aktif selesai.
