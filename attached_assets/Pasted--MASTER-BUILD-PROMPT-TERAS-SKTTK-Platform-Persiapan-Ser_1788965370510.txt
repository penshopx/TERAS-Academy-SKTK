# MASTER BUILD PROMPT

## TERAS SKTTK — Platform Persiapan Sertifikasi Kompetensi Tenaga Teknik Ketenagalistrikan

Build a production-ready web application called:

# TERAS SKTTK

**TERAS = Platform Persiapan Sertifikasi Kompetensi Tenaga Teknik Ketenagalistrikan**

Tagline:

> **Build Competence. Build Evidence. Build Readiness.**

TERAS SKTTK is a specialized capability development and pre-assessment readiness platform for people preparing for **Sertifikasi Kompetensi Tenaga Teknik Ketenagalistrikan (SKTTK)**.

---

# 1. CORE PRODUCT POSITIONING

TERAS SKTTK is NOT:

* a certification body;
* an LSK;
* an assessor;
* an official examination system;
* an official certification decision system;
* a replacement for an assessor;
* a system that issues an official SKTTK certificate.

TERAS SKTTK IS:

> A structured digital platform that helps candidates build competence, practice technical tasks, collect preparation evidence, receive feedback, remediate gaps, simulate assessment situations, pass internal safety gates, and understand their readiness before entering the official certification process.

Core principle:

> **TERAS prepares. Assessor assesses. Certification body decides.**

The application must NEVER display internal TERAS readiness as:

* "Competent";
* "Certified";
* "Passed SKTTK";
* "Official Certificate".

Instead use terminology such as:

* Ready for Official Assessment
* Developing
* Not Ready
* Preparation Evidence
* Readiness Record
* Capability Passport
* Internal Simulation
* Preparation Status

## Engine 2 — Diagnostic Engine

The first serious interaction after selecting a program should be Diagnostic.

Diagnostic evaluates:

### Knowledge

* concepts;
* principles;
* terminology;
* procedures;
* technical understanding.

### Experience

* work experience;
* exposure to relevant tasks;
* project experience.

### Practice

* ability to perform technical tasks;
* sequencing;
* troubleshooting;
* equipment identification;
* decision making.

### Safety

* K3 awareness;
* electrical safety;
* hazard recognition;
* safe working procedure;
* unsafe action recognition.

### Communication

* technical explanation;
* ability to explain procedures;
* ability to justify decisions.

### Evidence

* existing work records;
* previous training;
* practice records;
* supporting documents.

Diagnostic must NOT simply produce one score.

Generate:

> **Personal Competency Profile**

and:

> **Personal Readiness Map**

# 12. SAFETY GATE

This is one of the most important features.

Implement a HARD SAFETY GATE.

Core principle:

> **Safety failure cannot be hidden by an average score.**

Example:

```text
Knowledge       90
Practice        88
Evidence        85
Simulation      87
Communication   84
Safety          CRITICAL FAILURE
```

Final status:

```text
NOT READY
```

Never allow an average score to override a critical safety failure.

Safety must be represented separately from general performance.

Safety states:

```text
SAFE
ATTENTION
REMEDIATION REQUIRED
CRITICAL BLOCKER
```

Critical safety blockers must prevent:

```text
READY FOR OFFICIAL ASSESSMENT
```

until resolved.

# 14. READINESS LOGIC

Suggested model:

```text
Readiness =
Knowledge
+ Practice
+ Evidence
+ Simulation
+ Communication
```

However:

```text
IF Critical Safety Failure = TRUE
THEN
Status = NOT READY
```

Regardless of average score.

Also:

```text
IF required evidence is missing
THEN
Status cannot be READY
```

And:

```text
IF mandatory competency area is incomplete
THEN
Status cannot be READY
```

The architecture must allow administrators to configure thresholds.

Do NOT hardcode all thresholds.

Create configurable readiness rules.

```text
Register/Login
↓
Select SKTTK Program
↓
Complete Diagnostic
↓
See Competency Profile
↓
See Gap Analysis
↓
Receive Learning Plan
↓
Study LMS Module
↓
Complete Practice
↓
Submit Preparation Evidence
↓
Receive Feedback
↓
Perform Remediation
↓
Repeat Practice
↓
Complete Simulation
↓
Pass Safety Gate
↓
View Readiness
↓
Generate Capability Passport
↓
Move toward Official Certification Handoff
```

```text
Dashboard
Journey
Readiness
Capability Passport
Trainer Dashboard
```

No screen may falsely indicate readiness while a critical blocker exists.

# 61. CRITICAL CONSISTENCY PRINCIPLE

The following must always communicate the same learner condition:

> **Readiness ↔ Safety ↔ Evidence ↔ Assessment Simulation ↔ Capability Passport**

If:

```text
Safety = BLOCKED
```

then the system must not display:

```text
READY
```

anywhere.

If:

```text
Evidence = INSUFFICIENT
```

the system must not display:

```text
READY FOR OFFICIAL ASSESSMENT
```

If readiness changes, the change must propagate to the relevant dashboard and passport state.

# 63. FINAL PRINCIPLE

Build TERAS SKTTK as:

> **A system that transforms learning into demonstrable capability and demonstrable capability into measurable readiness.**

The ultimate product outcome is NOT:

> "Learner completed a course."

The ultimate outcome is:

> "Learner has built, practiced, demonstrated, reviewed, remediated, simulated, and documented the capabilities required for the target SKTTK preparation pathway, with safety blockers explicitly identified and readiness transparently communicated."

Build this as a serious production SaaS platform, not a prototype LMS.

The architecture must be clean, modular, auditable, secure, scalable, and ready for future integration with Gustafta and official certification workflows.
